# Translation workbenches

Open the [translation index](../index.html) and choose a subject. All 6,695
extracted entries are included, with Japanese source beside the current English.
Of these, 5,020 have editable contracts; 1,675 remain references. The
[coverage page](../coverage.html) accounts for each entry and links to the owners
of text rendered from graphics or generated by code.

## Editing

Subjects share one browser draft and one download. Choose a group, search by text,
subject or stable ID, and use **Needs attention** to find errors throughout the
script. Changes that affect an unchanged entry also appear there. Search and error
filters cross subjects. The first preview opens automatically.

- Prose uses the existing 72 scenes and balanced word wrapper. New readable boxes
  require `<page><box>`; `<page>` alone does not reset the pen or line cursor.
- Combat retains authored breaks and simulates native `<cF3>` rollback. The first
  110 group-8 entries use mode `$10`; companion talk has a two-line viewport.
  Every layout-distinct runtime-name combination is checked.
- Item/action messages retain conditional checkpoints. Messages without `<cF3>`
  use the owner's greedy wrapper. Downloads contain the authored draft.
- Item descriptions retain explicit title/body line breaks and fixed stat headers.
  Their mode `$08` canvas permits 11 composer lines. Change body wording and
  `<br>` positions together; the ROM allocator checks storage independently.
- Help retains its source line budget and critical controls. Notebook descriptions
  keep their exact one/two-line contract and are checked with the monster name;
  the preview includes that name row.
- Names and positioned labels use runtime/domain and direct-renderer budgets.
  Item-action ink cannot enter the cursor-only tile. Locations also satisfy their
  right-aligned panel limit.
- Glossary edits recompute collisions, matching definitions, source-term obligations,
  runtime widths, Notebook composition and consumers. Prefixes plus canonical item
  roots are included in the item-name domain.
- Blank Scroll roots are embedded in the native matcher. They remain references
  until the root and code owner change together. Disabled roots retain their
  sentinel; other recall roots use the project's 14-character field.
- Internal labels, password data, empty slots and UI entries without an approved
  standalone fit contract remain visible with a reason and cannot be downloaded
  as edits. This is separate from extraction coverage.

Use the installed 79-character English font and listed native symbols. Keep runtime
substitutions, source boundaries, effects and `<cF8>` selectors as required. Enter
inserts `<br>`; Ctrl/Cmd+Enter inserts `<page><box>`. Each entry identifies its family
and measured surface.

**Preview font** switches all previews between Classic and Shadowed with identical
advances. Dialogue uses the checked GB2 frame. Other previews show the family's text
canvas and line step, without the surrounding game screen. Shaded spans reserve
runtime widths, including the conservative 49px player-name bound. Player input
itself remains limited to six visible characters.

Invalid drafts are saved and can be downloaded with **Back up draft**. A newer draft
in another tab stops saving and offers recovery. Storage errors are shown. Keep
backups of unfinished work. The earlier prose editor keeps its separate draft and
uses the importer documented in [prose/README.md](../prose/README.md).

## Download and project import

The UTF-8 TSV format is `shiren-gb2-workbench-edits-v1`. Comment headers contain
catalogue/rules revisions and each edited entry's baseline hash, followed by
`id<TAB>english`. Only changed entries are included. Preserve metadata and intentional
spaces. Downloads include edits from every subject in the shared draft.

**Import edits** opens compatible TSV downloads or JSON draft backups. Unknown IDs,
stale baselines, incompatible rules and conflicting local edits are rejected before
merging. Compatible unfinished TSV text can be opened for repair.

```sh
# Check without changing project files; inspect the proposed diff.
python3 tools/workbench_web.py import "$ROM" changes.tsv
# Apply the validated result.
python3 tools/workbench_web.py import "$ROM" changes.tsv --apply
```

The importer independently encodes and measures the entire prospective workspace
using the Python owners. It runs full terminology lint, runtime-domain and combat
combination audits, menu/Notebook and input-name checks, allocation and a complete
in-memory ROM build. It then prepares all draft owners in a temporary workspace.

Prose edits update `script/editing/prose.tsv` and its generated draft; item/action
and combat edits update their respective `script/drafts/` owners. Ordinary text
updates its compact and rich category TSVs. Generated text and ownership hashes
are synchronized together. An unchanged prose draft can acquire different wrapped
breaks when a runtime name grows. Baseline/concurrent-change checks protect existing
work; a write failure rolls back files already changed by the importer.

After applying, regenerate both web catalogues and run the normal build and affected
game checks. Static checks cannot judge translation meaning, event timing, every
gameplay route or visual acceptance. A different-language translation also requires
project font and terminology changes.

## Maintenance

See the [site commands](../README.md#regenerate-test-and-preview). The catalogue derives
from `organize.py`, the font/codec, source controls, scene/draft owners, `build.py`,
`menu_text.py`, `layout.py`, `runtime_widths.py` and `lint_en.py`. JavaScript tests compare
every editable baseline and thousands of mutations with independent Python results.
No GB1 rendering limits are reused.

`build_pages.py` checks freshness and complete subject coverage before copying its
public-file allowlist. Japanese is deliberately bundled; ROMs, machine code, raw
extraction and saved games are excluded from the artifact.
