TEXT REFERENCE

Control code reference

Control codes tell GB2 when to break a line, wait, reset a box or insert a value from the game. This page explains the project’s spellings and editing rules. Click a code in either editor to open its explanation here.

Reading a code

Keep the angle brackets and spelling. Arguments are two-digit hexadecimal bytes: 1E is decimal 30. Letters such as NN, LL and HH below are placeholders, not text to enter. For a two-byte argument, LL is the low byte and HH the high byte.

The Japanese source and each entry’s checks determine which codes belong there. A code appearing in this reference does not make it valid in every entry. Keep runtime arguments, native selectors and required effects unchanged.

These are GB2 definitions. The ROM source composer expands F4–F6 before rendering; those bytes have different meanings in already-expanded renderer data. Use the named source forms below when editing the script.

Lines and boxes

CodeWhat it doesEditing guidance
<br>FDAdvances one physical line immediately and returns the pen to the left edge. It does not wait for input.Use for a measured line break. Enter inserts it. Dialogue and full-renderer text advance 11 pixels; the stepped renderer advances 16. Each surface has its own line budget.
<page>FBWaits for fresh input. It keeps the horizontal pen and physical line position.Keep required waits in order. A wait does not free a line or reset a box. In dialogue, the 9-pixel wait marker must start at 135 pixels or earlier. If words continue after a wait, keep their separating space.
<box>FCEnds the current renderer invocation. In dialogue, it resets the text surface for the next box. It does not guarantee a reading pause.Use <page><box> for an added readable dialogue box. Ctrl/Cmd+Enter inserts both. Preserve source box boundaries, including native standalone boxes; do not replace every box with a new wait.
<cF3>F3Marks a conditional soft-wrap checkpoint in the source composer. If expanded text reaches its 144-pixel threshold, it rolls back to the latest checkpoint and turns it into a line break. Otherwise the renderer ignores the marker.Keep at least one when required by the prose source. Place additional checkpoints at safe word boundaries where the entry permits them. A checkpoint after an overflow cannot rescue text before it. Other subjects apply their own source-control rules.
<hspace:NN>F7 NNAdds NN pixels to the renderer’s horizontal pen. The source composer does not count this spacing.Keep spacing required by positioned labels and other fixed layouts. The preview checks renderer spacing separately from composer width; extra spacing still has to fit the surface.

<page><br> waits and then advances a line within the same box. <page><box> waits and starts a fresh dialogue box. In prose, keep the break after a source wait, or replace that break with a box reset when needed to fit. Three physical lines remain the dialogue limit even across waits.

Runtime values

These insert text or values supplied while the game runs. Keep their arguments and occurrence counts. The same spelling can refer to different kinds of text in different records; the preview reserves the project’s measured width for that entry.

CodeWhat it doesEditing guidance
<copy:AA:BB:CC>F4 AA BB CCInserts an unsigned integer supplied at runtime. The legacy name is retained in extracted scripts; the first argument is the integer’s byte count, not a number of text characters to copy.Preserve all three bytes, for example <copy:01:19:C5>. Do not change the first argument to shorten the preview.
<name>
<name:NN>F5 FF / F5 NN		Inserts the player name. The argument-free spelling means the complete name; an explicit argument selects a bounded form.Keep the source form, including <name:00> where present. The localized player editor accepts six visible characters. The conservative 49-pixel reservation in legacy F5 checks is headroom, not permission for a seventh character.
<lookup:LL:HH>F6 01 LL HHInserts a table-selected runtime string.Keep the two argument bytes. The supplying code and record determine the string’s domain; do not substitute a guessed name.
<number:LL:HH>F6 03 LL HHInserts a cached runtime string. The legacy name does not mean the result is always a number. It may contain a name or another value.Keep the exact arguments and use the entry’s reserved width. Do not measure this as a fixed number of digits.
<sourceF6:MM:LL:HH>F6 MM LL HHPreserves an F6 source mode without giving it a guessed semantic name. MM selects the mode.Keep all three arguments. Modes 01 and 03 have the lookup and number spellings above. An unconfirmed runtime domain needs project investigation before an entry can be opened for editing.
<cF8>F8A native template escape whose following digit/lowercase selector run is consumed by game formatting code. The renderer itself treats F8 as a no-op.Keep the marker and its following native 0–9/a–z selectors unchanged and in order. In <cF8>g, g is a selector, not a word to translate: the bytes must stay F8 10, not localized F8 36.

Timing and effects

CodeWhat it doesEditing guidance
<delay:NN>FA NNSets the native character/timing delay from one byte. This is not a general instruction to pause for exactly that many frames.Keep required values and counts. Timing needs an in-game check; the text preview does not play it back.
<cF9:LL:HH>F9 LL HHPasses a two-byte little-endian effect argument to the native handler at 0:$3A4C. Individual effect meanings are not fully mapped here.Preserve the exact arguments and required count. Do not change it based on a guess about a sound, animation or other effect.
<cFE>FEA named no-op in the ordinary renderer, retained for lossless source decoding.Keep source occurrences where the entry requires them. A renderer no-op is not permission to remove bytes from records also used by native formatting code.

The production dialogue patch makes explicit <page> waits require fresh input. Cinematic records without that code retain native delay-driven automatic pacing. Keep their required controls and check the event in game.

Named glyphs

These are two-byte font glyphs, not timing or layout commands. Their distinct spellings preserve distinct source bytes. The editor accepts only the glyphs supported for that entry by the installed font.

TokenWhat it representsEditing guidance
<speaker>F2 24An opening speaker quote/separator in the Japanese font.An unmatched separator after a speaker name becomes Name: dialogue in English. A paired form may remain only when intentionally quoting a visible in-game label.
<speakerEnd>F2 26The closing counterpart to <speaker>.Review the pair as punctuation. It does not end a text box or a record.
<quoteOpen>F1 98A separate opening quote glyph.Its source bytes differ from <speaker> and ordinary corner quotes. Use the project’s English punctuation rules; do not treat it as a layout command.
<quoteClose>F1 9AThe closing glyph paired with <quoteOpen>.Keep quote meaning and pairing when translating. The font and entry checks determine which spelling is usable.
<cracked>F2 1EThe composite cracked-item mark. The production graphics pass changes its Japanese bitmap to (Cr), retaining the same script token and width metadata.Preserve the token where required. Do not replace it with guessed punctuation from the Japanese bitmap.
<passwordLeft>F2 4CThe named left password glyph from the reviewed font table.Part of the native password presentation. Follow the entry’s fixed/reference status; this is not a general text-box border control.
<passwordRight>F2 4EThe named right password glyph.Keep the corresponding native presentation. Password data is not ordinary translatable dialogue.

Raw bytes and authoring syntax

<HH>, such as <D2>, preserves a single byte for which the codec has no ordinary character spelling. It is not automatically a control: many native symbols occupy the D0–EF glyph range. Keep source identity and use only aliases accepted by the entry’s font checks.

{HHHH} preserves a two-byte glyph with an F0, F1 or F2 prefix. A form such as the reviewed {F174=明} is a byte-specific character alias, not a new glyph definition. Use the actual reviewed mapping in the project. The codec can preserve unknown source bytes even when the translation editor cannot safely render or accept them.

Record terminator — FF. The build writes the record ending. Do not type <FF> into a translation. An FF argument inside a complete control, such as F5 FF for <name>, belongs to that control and does not end the record.

<empty> is an authoring marker, not a ROM control. It identifies an intentional empty value in project files. A blank English project cell instead means untranslated/native fallback. Empty or internal slots shown as references in the browser do not become editable by entering this marker.

Using the codes in a translation

Keep each entry’s listed runtime substitutions, native selector runs, required timing effects and source boundaries. Prose wraps at word spaces; other subjects retain explicit line breaks or use their own project wrapper. Names, descriptions, menus and help text have different line, width and shared-dependency checks.

Choose Classic or Shadowed near the top of the editor to inspect the game font. Both styles have the same widths. Shaded runtime spans reserve measured space; they are not a prediction of the exact text that will appear in every playthrough.

Invalid edits stay in your browser and can be backed up. The changes download remains blocked until the entry and shared checks pass. Import the TSV with the project importer for the native owner checks and build validation, then review translation meaning, timing and appearance in game.
